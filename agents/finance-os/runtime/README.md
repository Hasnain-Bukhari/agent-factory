# Finance OS local core

This runtime contains gate-passed Phase 2 encrypted persistence, Phase 3 portable interchange/MCP, the Phase 4 synthetic ChatGPT interaction harness, the Phase 5 offline Telegram webhook adapter, and Phase 6 local dashboard/automation interfaces. It remains **synthetic-data only until an explicit real-data pilot approval**. The MCP service is loopback-only; no external ChatGPT connection, live Telegram/feed/notification connection, or public endpoint is included. Phase 6 is a transport-neutral local gateway and injected offline doubles, not a deployed website. It supports Apple-silicon macOS with Node.js 22. Encryption uses Node's maintained OpenSSL-backed `crypto`, persistence uses Node filesystem primitives, and the production key-provider adapter uses macOS Keychain through `/usr/bin/security`. Direct dependencies are lockfile-pinned Ajv 8.20.0, `@modelcontextprotocol/sdk` 1.32.2, and Zod 4.6.7.

Run `npm test` for the synthetic gate and `node bin/finance-os.mjs doctor` for a non-sensitive host check. `bin/finance-os-mcp.mjs` starts the authenticated Streamable HTTP endpoint only on `127.0.0.1`; it requires an owner-only credential file and never exposes raw file, store, or key tools. `src/telegram.mjs` and `src/phase6.mjs` are transport-agnostic clients with injected dependencies; gate tests use only in-memory synthetic substitutes and loopback MCP. Lifecycle, hosting, and threat boundaries are described in [`../references/operations.md`](../references/operations.md), [`../references/runtime-phase6.md`](../references/runtime-phase6.md), and [`../references/dashboard-automation-threat-model.md`](../references/dashboard-automation-threat-model.md). Do not initialize a real store, connect a live service, or supply personal records until the applicable disclosure, review, and explicit approval.
